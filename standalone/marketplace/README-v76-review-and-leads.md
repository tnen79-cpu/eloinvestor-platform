# إلو مستثمر v76 — مراجعات موثقة ومتابعة المهتمين

هذه نسخة تطوير كاملة فوق v75. لم تُنشر ولم تُطبق ترقياتها على قاعدة البيانات الفعلية؛ وصول الإدارة إلى مشروع Supabase الحالي مرفوض. العمليات الجديدة تتوقف برسالة واضحة حتى تتوفر دوال الجاهزية المطلوبة.

## السلوك الجديد

- قبول مستند واحد لا يمنح شارة التوثيق إذا بقيت مستندات حالية معلقة. جميع المستندات الحالية يجب أن تكون مقبولة؛ الملف المرفوض يطلب استكمال المستندات.
- صفحة verification.html تدعم الحساب أو مشروعًا مملوكًا عبر ?project=UUID، تعرض أسباب القرار، وتتيح استبدال مستند محدد مع الاحتفاظ بالنسخة السابقة. إعادة نفس طلب الرفع لا تضيف نسخة مكررة.
- قرارات التوثيق والنشر تتحقق من صلاحية الموظف، ومن نسخة البيانات التي راجعها، وتحفظ القرار وسجل الإدارة وإشعار المستخدم ضمن معاملة واحدة. عند فشل أي جزء يُلغى القرار. نشر المشروع لا يمنح التوثيق تلقائيًا.
- المستثمر يسجل اهتمامه دون مشاركة التواصل افتراضيًا. صفحة my-interests.html تتيح الموافقة أو إلغاء المشاركة أو سحب الاهتمام. الاهتمام القديم لا يُعاد تفعيله في فرصة أوقف نشرها.
- owner-leads.html تعرض الاهتمامات لمشاريع صاحب الحساب فقط. اشتراك فعّال يتيح مراحل المتابعة والملاحظات الخاصة والمحادثة الداخلية. الاسم والهاتف والواتساب تظهر فقط عندما يكون الاهتمام نشطًا والمستثمر موافقًا؛ لا تُرسل تفضيلاته الخاصة.
- يمنع تعديل الملاحظات من نسخة قديمة، وتُحجب البيانات المشتركة عند سحب الموافقة. لا يحذف سحب الاهتمام محادثة سابقة أو رسائلها.

## التشغيل

اقرأ README-v75-core-flows.md لترتيب الترقيات السابقة ومتطلبات Storage. بعد اكتمالها، طبّق:

`supabase/migrations/20261011233442_accountable_review_and_leads.sql`

الترقية تعيد حساب شارات التوثيق للمشاريع، ولحسابات لديها مستندات مستثمر، حسب المستندات الحالية. المشروع الذي لا مستندات له يعود إلى غير موثق. تظل قرارات نشره مستقلة. يمنع الإدراج والتعديل والحذف المباشر للمستندات من جلسات المستخدمين، ويُستخدم مسار التقديم والمراجعة بدلًا منها.

ترحيل الاهتمامات التاريخية من project_interests غير منفذ؛ لن تُعتبر البيانات القديمة موافقة جديدة على مشاركة الاسم أو الرقم. صفحات المتابعة الجديدة تستخدم سجلات الموافقة الجديدة فقط. الملفات المرفوعة التي فشل ربطها قد تبقى في Storage لإعادة المحاولة؛ لا توجد مهمة تنظيف آلية.

## التحقق

نجحت 11 مجموعة اختبارات محلية: قواعد الحساب والفلاتر والمقارنة، حماية الحسابات والملفات والمعاملات من v74/v75، واختبارات PostgreSQL محلية للمراجعة والتراجع عند فشل سجل التدقيق وصلاحيات الأدوار والموافقات والاشتراكات، واختبارات DOM لإرسال موافقة صريحة ورفض القرار القديم والحفاظ على إعادة المحاولة. نجح فحص تركيب JavaScript والروابط الداخلية وملفات JSON.

```sh
npm ci
npm test
```

PGlite واختبارات DOM لا تستبدل تجربة Supabase الفعلية أو فحص الموبايل بصريًا. لم يُجرَ اختبار متصفح بصري أو تسجيل حساب أو تحويل مالي أو إرسال رسالة حقيقية. يجب تطبيق SQL ثم تجربة حسابي مالك ومستثمر وموظفي النشر والتوثيق قبل التشغيل العام. نصوص الشاشات الجديدة الديناميكية عربية؛ لا تُعد هذه النسخة استكمالًا للترجمة الإنجليزية.
